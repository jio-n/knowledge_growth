# ADR-003: LLMプロバイダー抽象とオフラインモック

日付: 2026-07-11 / 状態: 採用

## 文脈
§25: 特定LLM/APIへの直接依存禁止。§30: APIキーが無くてもテスト可能であるべき(完了条件「テストまたは確認方法が存在する」)。

## 決定
1. `LLMProvider` インターフェース(complete/complete_json)+ 実装3種: anthropic(Messages API)、openai_compat(chat/completions — OpenAI/Ollama/LM Studio/vLLM互換)、mock。
2. SDKは使わない。httpxで直接呼ぶ。
3. **mockプロバイダーを一級市民にする**: 全E2Eフロー(登録→抽出→質問→保存→ノート→エクスポート)がキー無しで動く。モック回答には「モック回答」ラベルを必ず含め、実回答と誤認されないようにする。初期抽出はモック時ヒューリスティック抽出にフォールバックし、実用的な結果を返す。
4. 既定プロバイダーは `mock`(初回起動で必ず動く)。実利用時に config で切替。

## 理由
- テスト・CI・デモ・開発がAPIキーとコストから独立する。
- ヒューリスティックフォールバックは実LLMのJSON失敗時の安全網も兼ねる。

## 帰結
- ストリーミング応答は未実装(全プロバイダー同期完結)。長い回答で待ち時間が出る — roadmapに記載。
- hint引数(mockの出力分岐用)がインターフェースに存在する。実プロバイダーは無視する規約。
