# ADR-002: 全資料タイプを共通ブロック列へ正規化

日付: 2026-07-11 / 状態: 採用

## 文脈
対象資料は PDF/Web/テキスト/Markdown と多様(§3)。だが読解・質問・翻訳・アンカー・ノートの仕組みは共通でなければならない。

## 決定
ingest層(app/ingest/)で全タイプを `document_blocks`(kind/text/level/page/heading_path を持つ順序付きブロック列)へ正規化する。下流(コンテキスト構築・アンカー・翻訳・表示)はブロックのみに依存し、資料タイプを知らない。

- PDF: PyMuPDFで行抽出→フォントサイズ中央値×1.15超を見出し判定→段落クラスタリング。page保持。
- Web: readability本文抽出→ h1-h6/p/pre/blockquote/li/table/figcaption をブロック化。
- text/markdown: 行ベースパース(見出し/コードフェンス/リスト/引用)。

## 理由
将来の資料タイプ追加(特許・トランスクリプト等)= ingest実装1つ追加だけで全機能が使える。アンカーもブロック基準で統一できる(source_anchor_spec.md)。

## 帰結
- PDFの見出し判定はヒューリスティックで完璧ではない(2段組・スキャンPDF非対応)。ブロック粒度の誤りはアンカーの quote フォールバックで吸収する。
- 図・表は画像としては保持しない(MVP)。キャプションテキストのみ。図表画像の保持は roadmap。
