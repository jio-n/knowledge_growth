# プロダクトビジョン

最終更新: 2026-07-11 / 状態: 確定(v1)

## 一言で

**資料を読むたびに、自分の理解ノートと再利用可能な知識体系が育っていく、資料中心の研究読解ワークスペース。**

論文要約ツール・PDFチャット・翻訳ツール・メモ帳のいずれでもない。原文・翻訳・構造化抽出・LLM対話・自分のメモ・最終理解・関連知識を「資料」を中心単位として一体管理する。

## 解決する問題

| # | 問題 | 本プロダクトでの解決 |
|---|------|---------------------|
| 1 | LLM要約がその場で読んで終わる | 資料ごとの永続的な「理解ページ」。再訪時は前回の続きから |
| 2 | 有益な回答が後から探せない | 回答の全体/一部をワンクリックで理解ノートへ保存、検索可能 |
| 3 | 論文ごとにチャットスレッドが乱立 | チャットではなく資料が情報管理の中心単位 |
| 4 | 原文・翻訳・要約・メモが分散 | 1画面(読解画面)に統合、双方向リンク |
| 5 | LLM回答と原文事実が混ざる | 全知識項目に出所(origin)と情報種別(info_type)を必須付与 |
| 6 | 保存操作が煩雑で読書が中断される | AI保存先提案 + 2クリック保存、画面遷移なし |
| 7 | 知識がツール内に閉じ込められる | Markdown/JSONエクスポート、ローカルSQLite、ロックインなし |
| 8 | 数ヶ月後に理解過程を再現できない | 質問・回答・根拠原文・未解決事項を資料に紐づけて永続化 |

## 中心概念

- **ResearchSource(資料)**: PDF/Webページ/テキスト/Markdownを共通の上位概念として扱う。入力形式が違っても解析後は共通の「ブロック列」になり、読解・質問・保存・ノートの全機能を等しく使える。
- **理解ノート(Understanding Note)**: 資料ごとに1つ。自動抽出 + ユーザーが選んで保存した知識 + ユーザー自身の考察で構成される「生きた文書」。AIが勝手に確定・上書きしない。
- **知識項目(KnowledgeItem)**: 保存の最小単位。出所・種別・原文アンカー・検証状態を持ち、再配置・検索・エクスポート・AI再利用が可能。
- **原文アンカー(SourceAnchor)**: すべての知識・質問・回答は原文位置へ戻れる。

## やらないこと(Non-goals)

- 全回答の自動ノート化(ユーザーが選んだものだけ保存する)
- チャット履歴中心のUI
- 特定LLMプロバイダー/ベンダーへのロックイン
- クラウド前提の設計(ローカルファースト)
- MVP段階での: ベクトル検索、引用グラフ、Zotero/Obsidian同期、複数ユーザー

## 成功状態(§34)

数十の資料を読んだ後でも、1つのワークスペースから「何を読み、何を理解し、何を疑問に思い、何が未解決で、次に何をすべきか」を再現できる。蓄積した知識はMarkdown/JSONとしてアプリ外(Obsidian、GitHub、他のAIエージェント)で再利用できる。
