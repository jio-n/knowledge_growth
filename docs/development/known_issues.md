# 既知の問題・制約

最終更新: 2026-07-11

## 機能上の制約

1. **PDF見出し検出はフォントサイズヒューリスティック**(本文中央値×1.15超)。サイズ差のない見出し・2段組・スキャンPDFでは段落構造が乱れる。アンカーはquoteフォールバックで機能し続ける。対策候補: PyMuPDF block座標のレイアウト解析(roadmap)。
2. **Web本文抽出で h1 が落ちることがある**(readabilityがタイトル扱いで除去)。タイトル自体はメタデータで保持される。
3. **JSレンダリング必須・認証付きWebページは取得不可**(httpx静的取得)。回避: ブラウザで保存したHTMLをテキスト取り込み。open_questions.md #7。
4. **PDF表示モードでのハイライト描画は未対応**(テキスト表示では表示される。作成・保存は両モードで可能)。bounding boxアンカー導入時に対応。
5. **原文ペインの表示モード(PDF/テキスト)はリロード後PDFに戻る**(タブ・スクロール・ペイン幅は復元される)。
6. **回答はストリーミングされない**。実LLMで長い回答は10秒以上スピナーになる(roadmap フェーズ2-1)。
7. **検索はLIKE部分一致**。日本語の表記ゆれ・意味検索は将来(C-1)。

## 運用上の注意

8. **認証なし**: localhost想定。LAN/公開環境に置く場合は認証層が必須。
9. **マイグレーション機構なし**: スキーマ変更時は data_model.md の手順に従い手動対応。
10. **Windowsコンソール(cp932)**: サーバーログに絵文字を含む文字列を print すると UnicodeEncodeError になり得る(アプリ動作には影響なし。ログ追加時は注意)。
11. **同一資料の多重分析防止はUI抑止のみ**(APIを直接連打すると並行分析が走り得る。最後の完了が勝つだけで破壊はない)。

## テストのギャップ

12. pytest はテキスト資料のE2Eのみ。PDF/WebのingestはUI・手動で検証済みだが自動化されていない(次の追加候補: fixtureのPDF/HTMLでの ingest 単体テスト)。
