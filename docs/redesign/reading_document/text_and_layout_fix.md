# RDR-01: HTML段落監査と狭幅レイアウトの修正

対象: Draft PR #10 / branch `spike/reading-document-html-first`.
起点は `6ef178a2086c3400cb5843fd122901bd1661efea`。
修正は同じbranch上のみに反映し、mainと旧PR #9、およびユーザーのDBには触れない。

## 問題

- 元のHTMLで `wbr` が改行候補として使われると、旧サニタイザの許可リストにないため削除タグとして記録される。文字ストリームは同一であっても、旧監査はインラインタグ境界に空白を挿入して段落の不一致を誤検出する場合がある。
- 狭い画面で長いURL・識別子がページ全体を横に押し出す。
- 以前の監査は不一致の種類と差分量が数値として出ないため、実際に意味のある欠落があるか切り分けづらかった。

## 修正

- `wbr` を安全なvoid要素として扱う。元テキストを落とさず、イベント属性・任意styleの除去は維持。libxmlが後続テキストをwbrにネストした場合もマーカーの後に出す。
- 監査の段落比較は実際のHTML文字ストリームを使用し、インライン境界に架空の空白を挿入しない。元からある空白・`br`・ブロック境界を保持し、否定・数値・引用・単語境界・順番の変化は引き続き不一致として検出する。
- 最大20件の不一致について位置・文字数・増減数のみ記録し、本文やURL、AI応答は安全な監査成果物へ含めない。
- 一般文・長いURLを折り返し、表・数式・preは内部スクロールを許可する。画面全体を`overflow:hidden`で隠さない。
- 390px/1280pxのテストではローカル素材のみを使い、外部リクエスト・pageerror・画像欠落・文字欠落を検査。
- `rdr-html-2` / `rdr-live-2` とし、ReadingDocument schema v1・原HTML snapshot cache・fetch/robotsルールは維持。

## 検証と受入

前ターンの孤立した自作fixture試験では、既存関連52件と追加20件の計72件が成功（Chromium 390px/1280pxを含む）。
合成の段落7件が完全一致するようになり、長いURLのscrollWidthは819px→390pxに収まった。
これらは**実MMADの不一致が完全に解消した証明ではない**。

GitHub反映後の全pytestと実MMADのActions再検査、HTML/PDF同版内容の比較は別途確認する。
実データが不一致なら品質ゲートを緩めず、文字列を含まない数値診断で原因を絞る。
実MMADの原HTML/画像/本文をGitHubのcommitや公開artifactに保存しない。

既存のRDR-01目的（英文を正しく取得して構造化し、図表付きで読めること）を優先し、旧PDF glyph/crop方式へは戻らない。
